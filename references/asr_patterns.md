# 中文播客 ASR 常见问题与校对策略

本文件用于帮助 Agent 识别中文播客转写中的高风险位置。它不是自动替换词典；没有足够证据时，应保留原文并加入疑点清单。

## 1. 专有名词

ASR 容易把低频词替换为发音相近的常见词，尤其是：

- 人名、昵称、社交账号名
- 公司、品牌、产品和节目名
- 书名、电影名、地名
- 英文缩写和中英混说术语
- 行业术语

### 处理原则

1. 优先参考本期大纲和嘉宾资料。
2. 同一名词在全文出现多种写法时，先列出所有时间戳。
3. 只有正确写法得到确认后，才加入 `corrections.json`。
4. 无法确认时保留原文，并标记 `[⚠️?]`。

## 2. 中英混说

常见问题包括：

| ASR 形式 | 可能的正确形式 | 处理方式 |
|---|---|---|
| Open AI | OpenAI | 大纲或官方名称确认后替换 |
| Chat G P T | ChatGPT | 确认后替换 |
| A P P | App / APP | 按节目统一风格 |
| 英文名音译成中文 | 原英文名 | 必须核对资料或回听 |

不要只凭读音猜英文拼写。

## 3. 数字、日期和单位

数字错误很难从上下文中可靠恢复，也是发布后最容易造成事实错误的部分。

重点检查：

- 年份和日期
- 金额、百分比和倍数
- 集数、排名和版本号
- 时长、距离、重量等单位
- 电话、网址和账号

任何无法由大纲或上下文确认的数字都应进入疑点清单。

## 4. 否定和语气

ASR 漏掉一个“不”“没”“并非”，可能完全改变说话人的意思。

重点检查：

- 前后逻辑突然矛盾
- 回答与问题方向相反
- “可以/不可以”“是/不是”附近的断句
- 反问、讽刺和引用他人观点

不要为了让句子通顺而自行补写否定词。

## 5. 同音词和断句

中文口语中常见：

- 的 / 地 / 得
- 再 / 在
- 做 / 作
- 权利 / 权力
- 账户 / 帐户
- 由于停顿导致的错误分句

只影响可读性且含义明确时可以修正。涉及事实、身份或立场时应保守处理。

## 6. 整句乱码

### 识别信号

- 每个词都像中文，但整句没有语义
- 与前后话题突然断裂
- 出现主题之外的词汇
- 多位发言人的内容被合并
- 背景音乐或环境声被识别为讲话

### 处理方式

- 保留原文
- 标记 `[⚠️?]`
- 记录准确时间戳
- 给出前后各一句作为回听上下文
- 不根据大纲直接“补写”原句

## 7. 发言人识别

扫描开场部分，寻找：

- “大家好，我是……”
- “今天请到……”
- “欢迎……来到节目”
- 主播对嘉宾的称呼

如果一位说话人可能对应多个名字，先询问创作者。ASR 的发言人编号也可能在中途漂移，长节目应抽查多个时间点。

## 8. 疑点清单格式

```markdown
## 疑点清单

### 1. [人名] 嘉宾英文名
- 时间戳：00:12:34
- 原文：……
- 疑点：英文拼写无法由大纲确认。
- 请确认：正确拼写是什么？
```

每条疑点都应满足：

- 有时间戳
- 有原文上下文
- 说明为什么不确定
- 提出一个创作者可以直接回答的问题

## 9. 已确认术语

创作者确认后，将本期术语写入 `glossary/epXXX_confirmed_terms.md`。旧术语只能作为后续节目的参考，不能跳过语境直接替换。
